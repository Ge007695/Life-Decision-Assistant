# 生活决策助手 Life Decision Assistant

面向日常决策的规则引擎设计与实现——以深圳生活场景为例。

深圳大学学生创新发展基金基础实验项目（2026 年度），个人项目。

## 项目简介

把"规则复杂、普通人懒得算"的日常问题，做成一句话结论加一份可执行清单。四个场景：

| 场景 | 用户原本的状态 | 本项目的输出 |
|------|----------------|--------------|
| 出门 | 看到"湿度 92%、南风 3 级"，不知道今天该不该晾衣服 | "今天适合晾晒，11:00—13:00 晾出，18:00 前收衣" |
| 时间 | 记不清下个假期还有几天、哪天要补班 | "距元旦还有 41 天，1 月 4 日（周日）需补班" |
| 出行 | 假期要带什么全凭记忆，到了才发现少带 | "国庆 10-01 起，按最差那天准备：带伞、换防水鞋" |
| 花钱 | 实习工资被扣了一笔不知道为什么；分期"每期 0.6%"不知道真实成本 | "本月到手 5,040 元""真实年化 13.84%，约为名义值的 1.9 倍" |
| 办事 | 办证材料总漏，跑两趟 | 材料清单加勾选进度 |

技术形态：Vue3 静态站点 + 本地配置文件，**主流程无自建服务端**；v0.11.0 起提供可选账号，
登录后设置与记录通过云服务跨设备同步，不登录时全部数据只在本机（与下方 C1/C2 的偏离见设计说明书 1.4）。

## 快速开始

```bash
npm install
npm run dev        # 本地开发，默认 http://localhost:5173
npm run build      # 产出 dist/，可直接静态托管
npm run preview    # 预览构建产物
```

验证命令（结题与中期检查可现场跑）：

```bash
npm run test              # 173 条单元测试，每个规则含典型值/边界值/异常值
npm run lint              # 内核层纪律检查（禁止 fetch/window/document/localStorage）
npm run m1                # M1 判据：命令行输出合法的 DecisionResult
node scripts/verify-acceptance.mjs   # 25 项验收标准逐条核对
node scripts/ssr-check.mjs           # 五个页面渲染冒烟测试
```

## 目录说明

### 代码

```
public/data/     配置层：指数权重、假期、税率、穿衣表、全国城市、办事清单（改这里，不改代码）
src/core/        内核层：引擎、9 条规则、纯函数工具（禁止网络与 DOM）
src/services/    服务层：天气取数 + 24h 缓存、空气质量、历史归档、本地存储、政策读取、浏览器定位、云同步
src/components/  组件层：DecisionCard / ScoreBar / ActionList / FormField / TrendChart / CloudAccount
src/modules/     业务模块：outing（含 P2 四张卡）/ time / money / affairs
src/views/       页面：Home / Time / Money / Affairs / Settings
scripts/backtest/  回测与实验脚本（Python 标准库 + Node 复用内核）
scripts/build-cities.mjs  生成全国城市坐标（一次性构建工具）
docs/            设计说明书、核心契约、决策记录、周志
tests/           单元测试（node:test）
```

## 三条硬约束（任何设计决策不得突破）

1. **不设后端**。全部逻辑在浏览器执行，静态部署。唯一外部依赖是公开天气接口。
2. **不采集用户数据**。成绩、工资、地址一概不入库，只存浏览器本地；代码库里没有真实个人信息。
   （v0.11.0 起的可选账号同步与原意冲突，未决，见设计说明书 1.4。）
3. **不使用需登录的校内数据**。教务系统、校园网、校卡数据一律不碰。

## 两条开发纪律

1. `src/core/` 为纯函数层，禁止出现 `fetch`、`window`、`document`、`localStorage`（ESLint 强制）。
   回测脚本直接引用同一份规则代码，保证"线上跑的模型"与"报告里评的模型"是同一个。
2. `main` 为可运行分支，推送即部署。大改动先开分支验证，通过后合并。

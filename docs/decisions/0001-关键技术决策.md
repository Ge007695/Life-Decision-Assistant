# 0001 · 关键技术决策

> 记录“为什么这么定”，不是“定了什么”。每条三五百字，结题答辩被问到直接引用。
> 结构定义见 `docs/CONTRACTS.md`。

---

## 1. 配置文件放纯函数层，取数动作留服务层

**背景**：工作指导书 2.1 写“内核层启动时 `config.load()`”，但同一节又规定内核层不得发起网络请求。
在浏览器里读 `public/data/` 必须走 `fetch`，两句话字面上冲突。

**决策**：把“取”和“验”拆开。`src/services/config.js` 负责 `fetch` 六份 JSON；
`src/core/config.js` 只是纯函数 `createConfig(raw)`，做 Schema 校验与冻结。
Node 回测脚本用 `fs.readFileSync` 读同样六份文件，调同一个 `createConfig()`。

**收益**：校验规则只有一份，浏览器与回测脚本不可能出现“线上宽松、回测严格”的偏差。
内核层的纯净性也真正可被 ESLint 检查到——如果允许 `config.load()` 在核心里，`fetch` 迟早会混进来。

## 2. 天气接口选 Open-Meteo，仓库里不放任何密钥

**背景**：工作指导书 4.2 要求“密钥外置到 .env.local，前端直连要限域名白名单”。
但纯前端静态站点里任何写进构建产物的密钥都是公开的，白名单只能靠平台侧配置，学校项目没有这道闸。

**决策**：默认用 Open-Meteo——无需密钥、免费额度足够个人项目、支持历史与预报。
所有接口字段名集中在 `src/services/weather.adaptResponse()`，换接口只改这一个函数。

**收益**：从根上消除了“密钥进仓库”这个风险项（管理标准 8.4 整节不再适用）。
若日后改用和风天气（需要 key），密钥进 `.env.local`，`.gitignore` 已排除，构建时通过
`import.meta.env.VITE_QWEATHER_KEY` 注入，代码改动仅限 `weather.js` 的 `request()`。

## 3. holidays.json 用 `years` 映射，不是单年平铺

**背景**：工作指导书 3.3 的示例是单年结构（`meta.year` + 顶层 `holidays`）。
但 5.3 验收标准要求“切换年份后，无数据的年份显示待公布”。

**决策**：改为 `{ years: { "2026": {...}, "2027": {...} } }`，每年自带 `status`
（`official` / `pending` / `partial`）。2027 年现在是 `pending` 且数组为空——这是合法状态，不是缺数据。

**收益**：切换年份只是换一个键，页面不必判断“这一年有没有配过”；
新增年份不动代码，只加一个键。校验函数也据此放行 pending 年份的空数组，
避免把“政策还没公布”误判成“配置写错了”。

## 4. 返潮预警的 level 要反向

**背景**：`DecisionResult.level` 的统一语义是“对用户越好分越高”（4 最佳、0 最差），
首页横幅要靠它挑出“等级最低者”做风险提示。

**决策**：返潮是风险，条件命中越多越糟，因此 3 条全中 → `level: 1`（最差），0 条 → `level: 4`。
配置里 `levels` 的 `min` 字段仍按旧规矩表示“阈值”，但阈值是**条件命中数**而非分数，
`pickLevel()` 不适用于它，由规则内部自行查档。

**收益**：首页横幅不需要为返潮写特例——取 `runBatch()` 结果里 `level` 最小的一条即可。
若把返潮写成“命中越多分越高”，横幅会在回南天推荐“今天适合晾晒”，正是最该预警的一天。

## 5. 路由用 hash 模式

**背景**：交付要求是“一个可长期访问的网址”，托管平台未定（Vercel / GitHub Pages / 校内目录）。

**决策**：`createWebHashHistory()` + `base: './'`。

**收益**：刷新 `/time` 这类子路径在任何静态托管上都不会 404，不需要 `vercel.json` 重写规则、
不需要 GitHub Pages 的 404.html 兜底、不需要服务器配置。同一份 `dist/` 扔到任何目录都能跑。
代价是 URL 多一个 `#`，对本项目（纯前端工具站、无 SEO 需求）没有实际影响。

---

## 6. 首屏结论由 `runBatch` 统一产出

**背景**：工作指导书 8.2 规定只有三条跨模块联动，不允许模块互相调用内部函数。

**决策**：首页把当前天气一次性交给 `runBatch(['drying','damp','umbrella','clothing'], weatherInput)`，
拿到四个 DecisionResult 后：等级最低者做横幅（风险优先于好消息），其余做指数条。
时间模块要穿衣建议时，同样走 `engine.run('clothing', ...)`，不 import 出门模块的任何东西。

**收益**：四条规则共享同一次取数，天气接口一天只调一次；
模块之间零耦合，删掉任一模块不影响其他模块编译。

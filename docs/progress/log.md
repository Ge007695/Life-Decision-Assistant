## 2026-11-03（夜间）· v0.10.0 全国城市与自动定位

- 起因：用户提出「只能选四个城市太少，想选中国所有城市，并且有自动定位」。
  这不是加功能，是修一个会直接影响结论正确性的限制——城市只有四个，
  意味着大部分用户看到的是别人城市的穿衣与晾晒结论。
- 数据：`cities.json` 从 4 个扩到 370 个（34 个省级行政区，含港澳台与省直辖县级市）。
  由 `scripts/build-cities.mjs` 从阿里 DataV 行政区划 GeoJSON 生成，带 adcode、官方全名、行政中心坐标。
- 取舍：没用「名字→经纬度」的地理编码接口。搜「朝阳」这种名字会同时命中北京朝阳区和辽宁朝阳市，
  靠人口排序去猜，猜错用户看到的是另一个城市的天气且很难发现。行政区划 adcode 天然唯一，不用猜。
- 取舍：运行时页面不调用任何地图接口，城市表是构建期生成的静态文件（62 KB），断网照样能选。
- 取舍：搜索不做拼音首字母。拼音要额外带数据，而中文输入法打「sz」也是先上屏「深圳」再选中，汉字匹配够用。
- 新增：`core/utils/geo.js`（球面距离 + 最近城市）、`services/location.js`（定位封装，失败原因分五类）。
- 教训一：默认城市原代码写的是 `cities[0]`。四个城市时恰好是深圳，排序成 370 个后第一个变成「安庆」，
  默认城市会悄悄换人。这类错误不报错不崩溃，只会让每个新用户看到安徽的天气。
  已改为读 `cities.json` 的 `default` 字段。
- 教训二：列表按省排序后，选中的深圳落在「广东」段，打开设置在列表顶部根本看不到。
  补了进入页面时滚到选中项；定位成功后滚到新城市，手动点选不滚（避免列表跳动）。
- 验证：测试 107→129 全过；lint 零问题；M1 通过；验收 19/19；五页冒烟无 Vue 警告。
  真机链路（CDP 授权 + 伪造深圳坐标）实测：搜索「深」1 条、「广东」21 条、「zzzz」0 条带提示；
  点选杭州写入 `330100`；点定位匹配深圳并提示「约 3 公里内」。
  375 px 无横向溢出。
- 卡点：本机 Node 直连 raw.githubusercontent.com 会在 TLS 握手阶段被重置（curl 可通），
  所以城市数据源换成了国内可直连的阿里 DataV；脚本里也不再依赖 GitHub。

## 2026-11-03（深夜）· v0.11.0 账号与云端同步

- 验证：129 条单测全过、lint 零问题、五页冒烟无 Vue 警告、构建通过；已按约定发布 dist，线上入口 `index-DT2cHwbc.js` 与本地一致，线上设置页含「云同步」。
